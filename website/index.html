An open simulated framework for controlled experiments in robot learning

A robot arm, a table and a box of lettered blocks. You write the task as a goal, ToyBlocks generates the demonstrations, and you can train and evaluate policies on your own GPUs.

Code Documentation Dataset Models Blog post

Why blocks?

Kids learn a lot about space and planning from a pile of toy blocks: rebuilding a tower after it falls, turning a block over to find the letter they want. We wanted a robot learning setup with the same flavor. The domain is small enough that we know everything about every scene (each block, its letters, its pose, the goal), but the robot still has to push, flip, rotate and stack precisely, and some tasks take a dozen skills in a row.

Because nothing is hidden from us, a failed rollout is something we can actually debug. Was it the training data, the model, or the way we evaluated it? ToyBlocks is built so you can change one of those and hold the other two fixed.

What's in ToyBlocks

ToyBlocks has four main parts. Each has its own page here, and every page links to the matching section of the documentation.

Data generation

PDDL goals in, LeRobot datasets out. A TAMP planner plans every episode, motion-planned skills run hundreds of environments per GPU, check every step, and the episodes are rendered with domain randomization and annotated. Includes play data.

Training and evaluation

Train Molmo 2 and ManiFlow on generated data. Then replace the high level or the low level with an oracle to see which one is failing, replay datasets open loop, and send failure states back to data generation with TAMPER.

Sim-to-real Toolkit

Molmo 2 + ManiFlow, trained only on ToyBlocks data, spelled three-letter words on a real Franka FR3 in 15 of 30 attempts.

Agentic Framework

Each skill is exposed as an MCP tool, so a frontier model can drive the robot from camera images. We use it to study how these models search, plan and recover.

Example Evaluations

  • Does adding depth help compared to RGB alone?
  • If you train on stacks of 2 and 5 blocks, can the policy build stacks of 3 and 4? If blocks only spawn on the left of the table during training, does it work on the right?
  • How well do models handle long tasks, like finding hidden letters and spelling a word?

In our first experiments, ManiFlow, π0.5 and MolmoAct 2 all generalized poorly to new spatial configurations, which is exactly the kind of result we want to be able to dig into.

Getting started

You need Linux, an NVIDIA GPU and uv. The whole data generation pipeline fits on a 16 GB card.

git clone https://github.com/allenai/ToyBlocks.git && cd ToyBlocks
uv venv --python 3.11 && source .venv/bin/activate
git submodule update --init --recursive
uv pip install -e ".[dev,isaac,torch-cu128,vecgen]"
get-toyblocks-assets --asset-manifest asset_manifest.json
pytest tests/install          # checks the install in a few seconds
