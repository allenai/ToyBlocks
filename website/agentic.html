Agentic Framework

Letting a frontier model control the robot

agentic_robotics connects a vision-language model to ToyBlocks. The model sees the front camera and can only act through MCP tools, one per skill. It gets no success signal; it has to decide from the images when it's done, or when the task can't be done.

Skills as tools

The model works by pointing: most tools take a pixel in the camera image, and the skill acts on the block there. A small, robot-agnostic MCP host and an OpenAI-compatible model client (OpenRouter by default) run the loop, and ToyBlocks is connected through an adapter. The tools are:

Get Image Observation, Get Zoomed-In Image Observation, Pick Up Block, Stack on Block, Place on Table, Rotate Block, Flip Block, Return Arm to Home, Open Gripper, Close Gripper.

Every run saves its video, the full transcript, the config, and a summary that scores the final scene against the task's PDDL goal and records the tool calls and model cost.

Backends

The tools can be backed by two kinds of skills:

  • Oracle (the default) uses the scripted vecgen skills, the same ones that record our training data, planned with cuRobo on the simulator's ground-truth state. With these, failures come from the model's reasoning rather than from the skills. Needs the vecgen extra.
  • ManiFlow sends each skill to a trained ManiFlow policy through its policy server, so the model also has to deal with a learned controller's mistakes. Needs the maniflow extra and a checkpoint. ManiFlow skills

Web UI

There are a few ways to run and watch episodes in the browser:

  • menu: pick tasks one after another and interject while the model works.
  • page: a single model episode with a chat and interjection page.
  • human: you call the skills yourself, the same way the model would. Useful for checking that a new task is solvable.
  • portal: browse finished runs with their videos, transcripts and scores.

Docs: web UI and portal

Adding a task

Tasks are the same PDDL problems the data generation pipeline uses, so any ToyBlocks task generator works here. Write or generate the PDDL, register a TaskConfig with the prompt and a tool-call budget, build it with generate-env, and try it yourself in human before handing it to a model.

Experiments

We've used it for three kinds of experiments so far:

  • Search and spell. The letters needed for a word may be hidden, so the agent has to flip and turn blocks to find them before stacking the word. Half of the scenes don't contain all the needed letters, and then the right answer is to say the task is impossible.
  • Blocksworld goals on colored cubes: closed loop from images, open loop, and language-only planning in PlanBench format.
  • LEAP, where the agent first experiments with its own skills before starting the task.
30 / 30block-stacking planning tasks solved from text descriptions (Claude Opus 5.5)

24% → 63%with skill descriptions the agent learned itself; 36% with ones written by an expert
13%, 15%of errors: look-alike letters, and a letter stacked in the wrong orientation

Each experiment is a TOML file that pins the backend, model, checkpoint, camera, seed and skill settings, so runs can be repeated.
